⚡ Bolt: Replace multiple inline Intl.DateTimeFormat with getFormatter

💡 What: Replaced all expensive inline `new Intl.DateTimeFormat()` calls in `ActivityDutySchedule` with the cached `getFormatter` utility from `src/lib/date-time.ts`. Crucially, refactored `useState` calls in `DutySettings` to use lazy initialization `useState(() => getFormatter(...))` to prevent date formatting calculations from running unnecessarily on every component re-render.

🎯 Why: Instantiating `Intl.DateTimeFormat` is an expensive operation in Node/V8 and browsers. Doing this directly inside React component renders and especially inside `.map` loops or eager `useState` calls blocks the main thread and severely degrades performance, especially in list-heavy views or frequently updated components.

📊 Impact: Significantly reduces React render cycle latency. Recreating the formatter inline takes considerably longer (~59ms for 100 calls) compared to utilizing the cached version (~1.5ms). Lazy state initialization ensures the formatting overhead only occurs once during the initial mount, not on subsequent updates.

🔬 Measurement: Verify by rendering the `ActivityDutySchedule` component with many rows and interacting with it. Profiling with React Developer Tools will show a marked decrease in render time for the component and its children. Run `pnpm lint` and `pnpm test` to ensure functionality remains identical.
